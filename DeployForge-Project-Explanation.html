DeployForge

Instant preview environments for every Git branch.

DeployForge is a self-hosted developer platform that automatically converts a Git branch into an isolated, shareable application environment. It uses Docker containers, Nginx routing, and a React dashboard to reduce deployment setup from several manual steps to one branch push.

“Push a branch, get a working HTTPS preview link in under 15 seconds.”

Recommended implementation: Node.js + JavaScript backend, Express.js API, local MongoDB in Docker, React dashboard, Nginx, and Linux.

1. The Problem

When a developer wants to show a feature branch, they often need to build the application, start a container, find an unused port, configure a reverse proxy, set up HTTPS, and share the URL manually. This process is slow, repetitive, and error-prone.

Cloud preview tools solve part of the problem, but they can introduce vendor lock-in, recurring costs, and configuration overhead. DeployForge provides a lightweight, self-hosted alternative for small teams and hackathon projects.

2. The Solution

DeployForge watches Git branches and automatically creates an isolated preview environment for each branch. Every preview receives its own Docker container, port, proxy route, and public HTTPS URL.

3. How the System Works

Step 1: Detect Git activity

The backend receives a GitHub/GitLab webhook or periodically checks the repository. It identifies a new branch, a new commit, or a deleted branch.

Step 2: Build the application

The deployment service checks out the branch and builds its Docker image. Build output is stored and made available through the CLI and dashboard.

Step 3: Start an isolated container

Dockerode communicates with the Docker Engine API through the local Docker socket. The service starts a uniquely named container with CPU, memory, and lifetime limits.

Step 4: Allocate a port

The port manager selects an unused port from a configured range, records the assignment in MongoDB, and maps the host port to the application port inside the container.

Step 5: Configure Nginx

The backend generates a route such as feature-login.preview.example.com. It runs nginx -t before reloading Nginx so a bad preview configuration cannot break existing applications.

Step 6: Verify and share

An HTTP or TCP health check confirms that the application is ready. The CLI prints the HTTPS URL, and the React dashboard displays the deployment and its resource usage.

5. Why Node.js and JavaScript?

  • Fast development for a hackathon.
  • One ecosystem for the backend, CLI, and React frontend.
  • Strong support for webhooks, REST APIs, WebSockets, and Docker libraries.
  • Simple JSON-based data flow between Express and React.
  • Easy to explain and extend as a backend project.

6. Why Local MongoDB?

MongoDB Atlas may require IP allowlisting and can be inconvenient when a local public IP changes. Therefore, the hackathon setup uses MongoDB in a local Docker container.

Node.js backend ──────► MongoDB Docker container

Optional production setup:
Node.js backend ──────► MongoDB Atlas

This approach avoids Atlas connectivity problems, works offline, keeps the database private, and still preserves a cloud-ready architecture through the MONGODB_URI environment variable.

10. Security and Reliability

  • Never expose the Docker socket directly to the browser.
  • Sanitize branch names before using them in paths, hostnames, or container names.
  • Apply CPU, memory, process, and lifetime limits.
  • Validate Nginx configuration before every reload.
  • Protect dashboard actions and webhooks with authentication and signatures.
  • Do not allow arbitrary host filesystem mounts.
  • Reconcile MongoDB records with Docker containers after a backend restart.

12. One-Minute Presentation Explanation

DeployForge is a self-hosted preview deployment platform that converts every Git branch into an isolated Docker environment. A Node.js daemon receives branch events, builds the application, starts a container through Dockerode, allocates a safe port, and dynamically configures Nginx. After a health check, the system generates a public HTTPS preview URL and prints it in the terminal. The React dashboard shows all active previews, logs, CPU usage, and memory usage. We use MongoDB locally through Docker for a reliable hackathon setup, while MongoDB Atlas remains an optional production database. This gives developers fast feedback without cloud vendor lock-in or manual port forwarding.
